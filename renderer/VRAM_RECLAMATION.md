# Runtime texture VRAM reclamation

Patch 0032 adds general idle cleanup, independent of track transitions. It supplements existing explicit guest-unmap eviction and pressure-based GC.

Every second, reclaim up to 64 reloadable cached textures unused across two wall-clock epochs (at least 30 seconds; normally 30-60 seconds). Existing LRU submission ticks are sampled at 30-second intervals so the draw hot path does not read a clock for every texture touch. Images with GpuModified are excluded; the existing readback-aware collector and explicit unmap path retain responsibility for them. Image/view destruction remains deferred through the GPU scheduler.

The GPU-completed image recycle pool also expires entries after 30 seconds without reuse. These entries have already passed GPU completion, so their Vulkan images/VMA allocations can be destroyed directly under the existing pool mutex. The configured byte budget remains unchanged for frequently reused images.

This does not prove a leak or reclaim all categories of VRAM. Guest heap arenas, cached buffer allocations, Vulkan driver/pipeline caches, frame-generation resources and GPU-written images can retain memory independently. Vulkan memory allocators/drivers may retain reserved blocks even after individual resources are freed.

Source audit found sparse arena backing allocated with vkAllocateMemory but no runtime vkFreeMemory path. Patch 0034 releases an allocation only when every resident range sharing it is fully covered by one explicit guest unmap. The recorder finishes previous GPU work/binds, removes bindings from all arena aliases with a waited sparse-bind fence, drops resident-range and upload memo state, clears BDA entries, and frees the allocation. Live/partial allocations remain; separate partial unmaps are not accumulated by this first version. It intentionally does not evict based on inactivity or assume a track transition means data is dead. Build/reverse-apply passed; repeated-load VRAM and Vulkan lifetime validation pending.

Patch 0035 is opt-in diagnostic instrumentation (RYGT_VRAM_DIAGNOSTICS=1 plus Debug/Trace). It writes category snapshots every five seconds to stdout and suppresses other nonfatal ShadGT diagnostics for that process. Normal logging is unchanged without the environment flag. Categories: sparse backing bytes, live texture backing bytes and GPU-modified subset, recycled images, device-local VMA allocation/block bytes and slack, and separately imported host bytes. Texture/recycle allocations are subsets of VMA totals; never add them to those totals. VMA heap usage/budget fields may be fallback estimates because the allocator does not enable its memory-budget flag; compare external NVIDIA adapter readings separately and do not interpret the reported unattributed field as a reliable driver-memory measurement. Build and runtime snapshots verified. The local diagnostic wrapper temporarily selects Debug and restores the previous level on exit. Runtime reclamation policy unchanged.

Instrumented comparison (2026-10-19): fresh menu sparse=89 MiB, textures=325 MiB, device-local VMA allocations=750 MiB, VMA blocks=801 MiB, slack=50 MiB; NVIDIA adapter=1527 MiB. After one track visit and over 90 seconds back in the menu: sparse=859 MiB, textures=363 MiB, VMA allocations=815 MiB, blocks=1964 MiB, slack=1148 MiB; adapter=3632 MiB. These indicate sparse backing retention and VMA block reservation/fragmentation as the main measured targets, not predominantly live textures. This does not establish which sparse ranges are dead or whether the slack belongs to entirely empty blocks. Menu content/adapter totals fluctuate. Investigation results are preserved locally in investigation-build/vram-category-findings.txt and vram-category-comparison.log.

Patch 0036 accumulates exact-byte partial-unmap coverage across sparse backing ranges. Every range sharing a VkDeviceMemory allocation must be retired before it is unbound/freed. Map notifications and reused arena ranges cancel coverage. A separate short-held marker mutex avoids taking the buffer-cache mutex from registry-locked mapping callbacks. Eligibility is checked again after scheduler completion before unbinding. Existing Vulkan sparse unbind/fence sequencing remains.

Apply renderer/vma-patches/0001-trim-empty-default-blocks.patch inside shadGT/externals/vma before building 0036. It adds a locked empty-block removal method to VMA; the renderer calls it only for default device-local memory-type block vectors, respecting minimum block counts. A 30-second unload grace window schedules one trim; frequent unmaps do not continually postpone it. IsEmpty is mandatory. No allocations are moved, no occupied block is released, and custom pools are untouched. Diagnostic snapshots include cumulative sparse_freed_total and empty_blocks_freed_total in MiB.

Patch 0038 addresses a separate render freeze captured after further track loads. GPU recorder, submission and compiler workers were idle; guest Job#7 repeatedly faulted at GTSport.exe+0x1319e8b (a store through RSI). Opening only its 4 KiB destination page advanced execution briefly, then the same instruction faulted on another page. Direct inspection of the second page found one write watcher, CPU-modified buffer state, no GPU-modified state, and no registered or tracked texture covering it. UntrackHotPages left write_prot words uninitialized when a word contained no hot pages; GetWatcherBounds could consume them and add orphan watchers. Initialize every visited word before the cold-word early return. Production RegionManager regression test with patterned stack initialization fails on the original code and passes with this fix. The test is in renderer/validation/hot-page-watchers. Full build passed; runtime stability after this fix remains to be verified. No unowned-fault bypass or blanket protection removal is included in the source fix.
